## 产品范围与信息架构

### 公开首页 `/`

展示网站提供的化学学习内容、真实课程入口和最近发布的笔记。主操作是开始学习与浏览笔记；技术栈、环境变量和开发配置放入维护文档。

### 学习中心 `/learn`

按实际存在的学科、章节组织内容，提供清楚的章节顺序、当前阅读位置和可用的学习进度。空分类明确显示状态，不编造课程数量或学习统计。

### 阅读页 `/learn/[subject]/[chapter]` 与 `/notes/[slug]`

统一标题、分类、正文排版、公式、图片、返回导航与访问策略。课程有上一章、下一章和完成操作；笔记支持数据库中合法的既有 slug，包括含路径分隔符的旧记录。

手机端优先显示阅读内容，以可展开目录代替整段侧栏堆在正文之前。数学式和代码块在容器内滚动，避免撑破页面。

### 账户 `/account`

展示真实登录状态、已完成章节和继续学习入口。进度由服务端写入数据库，刷新后仍保留。匿名、无权限、依赖暂不可用应有不同反馈。

### 管理后台 `/admin`

保留管理员认证，统一文章和章节的列表、编辑、预览、保存和发布入口。发布前验证标题、slug、正文和数学内容；保存失败保留编辑内容。后台发布后前台与目录读取同一个内容服务。

### 中英文双语

- 前台和后台都提供清楚的“中文 / English”切换入口；导航、登录、账户、进度、表单、加载、空状态和错误提示都有两种语言。
- 记住所选语言，刷新和站内导航后保持一致；保留现有链接的可访问性。
- 同一章节的中文与英文标题、摘要和正文通过统一内容标识关联，切换语言后停留在对应章节，学习进度共用一份。
- 后台可分别编辑、预览和发布中英文版本，明确展示各语言的可用状态。
- 缺少译文时展示原文并用当前界面语言标明缺少翻译，不把原文冒充为已翻译内容，也不自动发布机器译文。
- 保持数学公式、符号和单位一致；中文保留有助于学习的英文科学术语。
- 根据当前语言设置页面 `lang`、标题、日期格式和可访问名称；验证英文较长文本在手机端的布局。

## 技术方案

保留 Next.js App Router、TypeScript、Prisma 和 NextAuth 的现有基础，优先修复连接和数据模型边界，不为了重构而更换所有框架。

- **数据库**：保留已核实的既有应用目标 `postgrese/public`、原有数据与迁移历史，不为此次重构搬迁到新建的 `chemistry` schema。默认 `postgres` 数据库的 `planner` 及 Supabase 管理的 schema 不在改动范围内。集成验证使用单独的临时测试 schema，测试结果不等于既有应用或生产迁移已执行；Production 目标仍需解除 Vercel 403 后核对。
- **内容**：由服务端内容服务统一读取与校验；数据库作为可编辑内容的来源。保留本地 MDX 样例，提供明确的导入方式与旧链接兼容，不在页面请求期间偷偷写入数据库。
- **双语**：统一管理界面文案与当前语言；内容翻译与章节身份分离，权限和学习进度不因语言产生重复记录。预览和发布使用相同的语言选择及缺译回退规则。
- **权限**：在服务端集中判断公开阅读、受限预览、登录与管理员权限。列表、直接链接、课程路由、预览和写接口共用策略。
- **认证**：保留 Google 登录和服务端会话，明确配置缺失和数据库不可用时的行为；不把连接失败伪装成正常退出登录。
- **图片**：使用专属 Supabase Storage bucket，通过受保护的服务端接口上传、记录和删除；管理凭据仅存在于服务端配置。
- **进度**：以当前登录用户、真实可访问章节和明确目标状态更新；重复提交保持结果一致。
- **接口**：共用输入校验与错误响应；未知记录、无权限、冲突和依赖不可用有稳定状态，日志不包含密码或连接串。
- **支付**：当前 Stripe 未配置。若本次纳入收费，须单独验证 webhook 幂等、事件顺序与购买/订阅权益，保证取消订阅不会撤销独立永久购买。

## 测试策略与验收

- 权限测试覆盖匿名、普通用户、授权用户和管理员；私有正文不能从替代路由或直接链接读取。
- 内容流程覆盖后台创建、修改、发布，以及目录和阅读页显示同步。
- 中英文分别验证首页、目录、阅读、登录、账户和后台；切换及刷新后保留语言，缺译提示清楚，语言切换不重置或重复计算学习进度。
- 后台的中英文编辑与预览对应正确语言；任一语言的草稿不能通过另一个语言入口绕过发布状态或权限。
- 校验测试覆盖无效 JSON、错误类型、重复或非法 slug、缺失记录和无效正文。
- 进度测试覆盖真实章节、当前用户隔离、刷新后保留与重复请求。
- 图片验证覆盖持久 URL、失败清理，以及重新部署后可读取。
- 浏览器验证首页、目录、阅读、登录、账户和后台；登录成功流程需要可用 OAuth 配置及用户参与授权。
- 在 320、768、1024 和 1440px 宽度检查布局；键盘可操作所有主要控件，表单有可访问名称。
- 数据库不可用时显示可恢复状态，不泄露内部错误、凭据或堆栈。
- lint、类型检查、行为测试和生产构建通过后，形成可审阅的部署候选版本。
- 生产数据和部署验证必须使用真实已确认的连接目标；本地测试或 mock 不能代替线上连接验证。

本轮本地验收已完成：隔离数据库的 13 组 HTTP 验证覆盖数据库会话、管理员 CRUD、两种语言和编码 slug、无权限写入、无效 JSON 与跨源保护、进度重复请求与账户、草稿/私有正文保护、安全预览、Storage 缺配失败，以及内置内容改名与删除保护。全部三条迁移与 14 张表的 RLS 在临时 schema 验证；测试 `User`、`Content`、`Progress`、`Session`、`ImageAsset` 归零后已删除临时 schema，原 `public` 计数与迁移历史保持不变。
